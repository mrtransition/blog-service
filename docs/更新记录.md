## 一、Phase 0 前置核实

### 0.1 路径解析现状（更新前）

| 入口 | 用户可控输入 | 更新前防护 | 结论 |
| --- | --- | --- | --- |
| `GET /blog-files/*` | URL 路径 | `http.FileServer(http.Dir(absBlogDir))` 做词法路径清理，限制在根目录内 | 词法安全，但会跟随指向根目录外的符号链接；目录列表开启 |
| `GET /api/file?path=` | query `path` | `filepath.Clean` + `filepath.Join` + `filepath.Rel`，`strings.HasPrefix(rel, "..")` 拒绝逃逸 | 仅词法校验；符号链接可逃逸；任意扩展名可读；以 `..` 开头的合法文件名会被误杀 |
| `GET /api/tree` | 无 | 递归使用内部生成的相对路径 | 安全 |
| `GET /api/config` | 无 | 只读配置 | 安全（会返回根目录绝对路径，属信息暴露，非本次范围） |
| `GET /` 及其它 | URL 路径 | `go:embed` 的 `embed.FS` | 安全 |
| `-dir` / `config.json` 的 `blogDir` | 启动参数/配置文件 | 无校验 | 属可信输入；启动时解析为绝对路径 |

结论：真正裸奔的是 `/api/file` 的符号链接逃逸，以及 `/blog-files/` 的符号链接逃逸与目录列表。

### 0.2 静态资源服务方式（更新前）

- `public/index.html` 通过 `//go:embed public/index.html` 嵌入，是唯一的嵌入资源。
- `/` 使用 `frontend.ReadFile` 直接写出，没有 `ETag`、没有 `Cache-Control`。
- 其它路径走 `http.FileServer(http.FS(frontend))`。
- `embed.FS` 的 `ModTime` 为零值，`Last-Modified` 不可用；无 ETag 时浏览器会启发式缓存，替换二进制后可能继续使用旧页面。
- 结论：`embed.FS` 零 ModTime 问题确实存在，需要内容哈希 ETag。

### 0.3 Go 版本与方案选型

- `go.mod` 声明 `go 1.21.13`，`os.Root` 需要 Go 1.24+，因此按计划回退到 `filepath.IsLocal` + `EvalSymlinks` + 根目录前缀校验。
- 未上调 `go` 指令，保持单二进制在旧工具链上的可构建性。
- 已按 rollback_policy 在代码注释中记录 TOCTOU 残余风险：校验与 `os.Open` 之间若本地符号链接被替换，仍有理论窗口；多用户部署时应升级到 `os.Root`。

### 关键实现说明

- **路径防护**：`resolveInsideRoot` 先 `filepath.IsLocal`，再 `EvalSymlinks`，最后与启动时已解析的根目录做前缀比较（Windows 大小写不敏感）。`safePathMiddleware` 在路由前拦截 `..`、`%2e`、`%5c`、`%00`，避免 ServeMux 301 重定向绕过校验。
- **静态文件**：`serveBlogFile` 自行 `os.Open` + `http.ServeContent`，保留 Range/Last-Modified，禁用目录列表，拒绝非常规文件。
- **ETag**：`sha256(public/index.html)[:16]` 十六进制加引号；弱比较支持 `W/`、逗号列表与 `*`。
- **快照**：`Snapshot{Articles, Tree, Generated}` 不可变，整体原子替换；`/reload` 先扫描成功再替换，失败保留旧快照。
- **草稿**：前缀与 frontmatter 同时支持（计划允许二选一，这里取并集，前缀仍是文档推荐方式）。前端 `loadTree`/`hashchange` 在树中找不到路径时仍直接调用 `/api/file`，因此 `/#/目录/_draft.md` 可直接预览，但不会出现在导航与 feed。
- **feed**：`encoding/xml` 生成，标题/日期/摘要来自快照；日期缺失回退 mtime；摘要剥离代码块、图片/链接语法与 HTML 标签；文章链接为 SPA hash 形式 `/#/<编码路径>`。

## 三、与计划的偏差

1. **架构差异**：计划假设 Go 侧存在 Markdown→HTML 渲染与 `template.HTML` 模板，实际项目由浏览器端 marked 渲染，Go 只返回 JSON。因此：
   - P2-1（bluemonday）无法按原描述接入；且其触发条件（接受非作者内容/公网多用户）未满足，第一轮保持 pending（第二轮已用 DOMPurify 完成，见第六节）。
   - P2-3（文章页 og 标签）没有服务端文章页可注入，触发条件（公网部署需求）也未满足，第一轮保持 pending（第二轮已新增 `/article/` 入口与 `/sitemap.xml`，见第六节）。
2. **RSS 链接**：第一轮 feed 使用 `/#/...` hash 链接。第二轮已改为 `/article/<编码路径>` 的服务端入口（返回带 og/canonical 的 SPA 外壳），阅读器与爬虫均可获得真实 URL。
3. **`.md` Content-Type**：静态访问时依赖系统 MIME 数据库，Windows 上通常为 `text/plain`；不影响页面内 iframe/接口渲染。
4. **未做（第一轮）**：P3-1（Webhook 鉴权）、P3-2（Basic Auth）触发条件均未满足，第一轮保持 pending；`/reload` 已满足“默认仅回环可访问”的核心诉求。第二轮已完成共享密钥与可选 Basic Auth，见第六节。

### 关键实现说明

- **XSS 清洗**：在 `marked.parse` 与 `innerHTML` 之间调用 `DOMPurify.sanitize(rawHtml, { USE_PROFILES: { html: true } })`。若 DOMPurify 或 marked 未加载，降级为 `escapeHtml` 的 `<pre>` 文本，绝不直接注入原始 HTML。HTML 文章 iframe 的 `sandbox` 移除 `allow-scripts`，仅保留 `allow-same-origin` 以维持目录跳转。
- **前端资源本地化**：marked 18.2.1、DOMPurify 3.5.0、highlight.js 11.9.0 放入 `public/vendor/`，通过 `go:embed public` 随二进制分发；`handleIndex` 用 `fs.Sub` 暴露 `/vendor/` 静态资源，不再依赖外部 CDN。
- **frontmatter 展示**：浏览器渲染 Markdown 前剥离文件头部的 `---` 元数据块，避免标题/日期在正文中重复出现；服务端仍用同一块数据生成标题、日期与草稿标记。无 frontmatter 的文章不受影响。
- **文章入口**：`/article/` 在快照中查找非草稿文章，并用 `resolveInsideRoot` 确认文件仍在根目录内；找不到、草稿或文件已删除均返回 404。页面替换 `<title>` 并注入 `og:title/description/url/site_name`、`article:published_time`、`link rel=canonical`；内联脚本用 `history.replaceState` 把地址规范化为 `/#/<编码路径>`，随后由现有 SPA 路由加载正文。
- **Sitemap**：`xml.MarshalIndent` 生成 `urlset`，`loc` 为 `requestBaseURL + /article/<escapeRelPath>`，`lastmod` 取文章日期；草稿跳过。
- **监听与鉴权**：`bind` 空值规范化为 `127.0.0.1`，地址用 `net.JoinHostPort` 拼接（兼容 IPv6）。非回环监听时启动日志提示暴露风险，并根据是否配置 token/认证输出对应警告。`/reload` 豁免 Basic Auth，避免流水线维护两套凭据；本机请求直接放行，外部请求校验 `X-Reload-Token` 或 `Authorization: Bearer`。
- **配置**：新增 `bind`、`reloadToken`、`authUser`、`authPass` 字段及 `-bind`、`-reload-token`、`-auth-user`、`-auth-pass` 参数；旧 `config.json` 缺少 `bind` 时按 `127.0.0.1` 处理。


CDN 不可达时，生产页面走安全降级分支：显示转义后的纯文本，不执行任何脚本；这保证了离线环境的安全性，但 Markdown 排版会退化为纯文本。

### 残余风险与建议

- Basic Auth 与 reload token 在纯 HTTP 下仍可能被嗅探，公网部署必须置于 HTTPS 反向代理之后。
- 前端依赖 CDN 的 marked/DOMPurify/highlight.js；完全离线部署建议将这些库改为本地静态资源并纳入 `go:embed`，同时保留清洗失败时的转义降级。
- 非回环监听时，`/api/config` 会返回博客根目录绝对路径；如介意信息暴露，可在反向代理层限制或后续移除该字段。
